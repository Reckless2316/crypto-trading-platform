## Cases to carry across task boundaries

- **Late and corrected fills (Tasks 2/3/11/13; Critical):** a late fill after CANCELED/FILLED is still journaled once, creates a reconciliation incident when cumulative amounts disagree, and blocks fresh entries. Same trade ID with changed fee/base/quote data retains original payload, verifies correction, appends a uniquely keyed compensation and recomputes current balances/risk. Duplicate correction is a no-op only with identical content. Preserve historical marks and add findings; never erase prior evidence or clear a drawdown latch after a favorable correction. Sources: A:288–292,330; P:190,592–593.
- **Capacity conservation (Tasks 2/11/12/13; Critical):** reconcile cash, native holdings, outstanding base/cash/fee reservations and pending modeled-loss budget after every partial fill, cancel/fill race and correction. Credit a fill once; do not count both original reservation and consumed notional as available cash. Do not credit unsold inventory or reserve only a replacement when its predecessor could still fill. Sources: A:246,256–258,265,335–337.
- **Control authorization is more than an allowlist (Tasks 14–17; Critical):** request ID binds actor/account/mode/epoch/payload; repeated identical request returns original receipt, changed payload rejects. Bound message size/fields and authenticate socket peer plus role capability. `resolve_review` requires linked finding, reconciliation and fresh checks, creates no permit, and cannot clear drawdown. Sources: A:22,341,383–385; P:632–634.

## Plan wording issues, separate from acceptance gaps

1. **Activation predicate differs; conductor resolved:** A:397 says activation while unarmed **or** after pending intents reconcile; P:663 requires an “unarmed/reconciled safe transition.” Follow the latest explicitly approved Plan: activation requires unarmed **and** all pending intents reconciled into a safe transition, with no unresolved UNKNOWN intent, at the decision boundary; activation remains operator-authenticated. The conductor will clarify architecture/Task 15 brief. This implements the approved Plan and introduces no approval gate.
2. **Approval hash ambiguity is already resolved:** A:192 includes gate approvals in CandidateBundle while A:397/P:663 require content-bound approvals. Hashing the complete package as the approval target would be self-referential. The conductor's Task 15 clarification specifies core identity excluding embedded approvals and separate package hash. Preserve it; this report does not repeat Task 1's implementation review.

No other contradiction in the reviewed requirements requires a scope change. Primitive examples (`missing_approvals`, `command_allowed`, `reservation_releasable`) expressly sit within fuller integration contracts and cannot alone demonstrate task completion (P:47,616).

## Task 19: replay correctness versus predictive validation

**Important acceptance gap:** event/receipt/knowledge cutoffs, future-field perturbation, purging and an untouched data split do not establish that a contemporary model, rubric, thesis or chosen universe lacked knowledge of historical outcomes. A modern Jev run over old observations can demonstrate deterministic replay/risk behavior while remaining contaminated for predictive evaluation. Sources: S:62,148; A:232–236,389–397; P:789–808.

Require evaluation manifests to record model/version availability and available training-cutoff evidence; first committed schema/rubric/feature/label/cost/eligibility/universe-selection methodology; calibration training cutoff; split commitment and holdout exposures; and the origin/time/hash of each forecast. Preserve excluded/delisted/ineligible candidates where the approved selection methodology requires them, avoiding selection by later success. Unknown model training contamination is reported as unknown, not inferred safe from a pinned model ID.

For promotion-eligible predictive evidence, use either verifiable historical forecasts and point-in-time methodology/model availability, or a genuinely forward shadow cohort collected after the complete evaluated artifacts and universe-selection methodology were frozen. Freeze selection rules, not necessarily membership: prospective membership changes must follow those rules using only contemporaneous evidence. Forecasts must be durably timestamped before label outcomes; later schema/model/selection changes start a new sealed cohort or follow the already approved precommitted evaluation protocol. Synthetic or retrospective fixture runs remain implementation evidence only. Keep all existing training/calibration/test floors, effective independent block rules, Holm/bootstrap/net-cost criteria and live approval boundaries unchanged. If available evidence cannot meet those conditions, Build may finish while promotion remains unavailable (P:807).
