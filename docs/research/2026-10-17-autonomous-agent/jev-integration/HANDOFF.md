## Conflicts and unresolved protocol details

1. **Documentation example contradicts the formula.** The HTTP Choice example uses probabilities (.88,.12,0) with confidence .81; the published three-option formula gives .82. Do not copy this as a valid fixture, loosen the approved 1e-6 tolerance, or silently use top probability. The formula remains the approved validation contract. Any observed contradiction must HOLD and block promotion pending resolution. [API](https://docs.typesafe.ai/api), [Confidence](https://docs.typesafe.ai/confidence).
2. **Provider advice differs from the approved retry policy.** Public docs recommend retries for 429/529; SDK defaults retry. Task 7 requires one attempt and zero retries, including 429, 529, other 5xx, timeout and connection failure. The SDK explicitly supports `RetryPolicy(max_retries=0)`. [Retries](https://docs.typesafe.ai/sdk/python/api/retries).
3. **A timeout option is not an end-to-end deadline.** The SDK documents per-operation HTTP timeout and a retry budget, not a server deadline/echo contract. Task 7 must enforce one local monotonic deadline across send, receive, parse and validation: the earlier of JudgeRequest’s deadline and the <=1,000ms total budget; dispatch also requires snapshot age <=2,000ms. Check completion against that deadline, cancel/ignore late results and never retry. No server deadline field/header was found in the reviewed public contract. [Async client](https://docs.typesafe.ai/sdk/python/api/clients/async), [Retries](https://docs.typesafe.ai/sdk/python/api/retries).
4. **SDK compatibility is not established.** Current Python documentation uses `httpx2` transport/client types, while Task 7 specifies injected HTTPX transport. Use the approved direct HTTP contract with HTTPX unless an explicit dependency review proves a pinned SDK compatible. Do not invent SDK imports or replace the transport type without review. The SDK also ignores extra response fields by default, which does not satisfy the application’s strict validation by itself. [Async client](https://docs.typesafe.ai/sdk/python/api/clients/async), [SDK responses](https://docs.typesafe.ai/sdk/python/api/types/responses).
5. **No public state-token proof found.** Reviewed documentation index, HTTP API, models and SDK contract pages did not supply a tokenizer identity/artifact, state-only counting endpoint or approved conservative bound. Scoped official-domain searches also returned no result. This is a bounded evidence gap, not proof that no such facility exists. Do not invent `/tokenize`, use another model’s tokenizer, count characters, or subtract question tokens from total usage. Task 5 must raise `TokenAccountingUnavailable` until provider-approved proof exists. [Index](https://docs.typesafe.ai/llms.txt).

The public pages do not document an echo of local request ID, state hash, bundle hash, boot ID or deadline. Bind these to the outstanding local transport operation and authenticated REFLEX/authority envelope; retain exact outbound bytes/hash and question set, raw response bytes/hash, resolved model, provider header when present, timestamps and deadline outcome. Do not populate “echoed” fields by copying local values and call that vendor verification. If vendor attestation of input hashes is required, that remains unsupported by this public contract.
